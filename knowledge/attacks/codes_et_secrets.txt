CAPTURE DES CODES À USAGE UNIQUE ET DES SECONDS FACTEURS

Document de doctrine adverse. Il décrit des mécanismes d'attaque observés, les
marqueurs qui permettent de les reconnaître, et surtout ce qui ne les prouve
pas. Il ne constate aucun fait sur un message particulier : il aide à qualifier
un faisceau d'indices déjà observé.

Cette famille a une particularité que le jugement doit garder présente : les
messages hostiles y ressemblent beaucoup aux messages légitimes, car les deux
parlent des mêmes objets - un code, une connexion, une vérification. La
distinction ne tient pas au vocabulaire mais au sens de la circulation.

1. La distinction fondatrice : fournir n'est pas réclamer

Un service qui envoie un code de vérification le FOURNIT. Le message contient le
code, n'attend aucune réponse, et souvent avertit lui-même de ne le communiquer
à personne. C'est le fonctionnement normal de l'authentification à deux
facteurs, et c'est du courrier attendu.

Une attaque RÉCLAME le code. Elle demande de le renvoyer, de le saisir sur une
page, de le dicter au téléphone ou de le confirmer à un « conseiller ».

Marqueurs de la réclamation : demande de communiquer, renvoyer ou confirmer un
code reçu ; formulaire distant demandant un code à six chiffres ; invitation à
rappeler un numéro pour « valider » ; message qui prétend que le code précédent
a échoué et qu'il faut le retransmettre.

Ce qui ne prouve rien, et c'est l'erreur la plus coûteuse de cette famille : la
seule présence d'un code dans un message ne constitue aucune charge. Un message
qui affiche « votre code est 481920 » ne demande rien. Traiter la mention d'un
code comme une tentative de capture reviendrait à retenir toutes les connexions
légitimes du destinataire, c'est-à-dire à casser son accès à ses propres
services. De même, l'expiration rapide annoncée par un tel message est
intrinsèque au mécanisme : ce n'est pas une pression, c'est une propriété.

2. Le relais en temps réel

L'attaquant se place entre la victime et le service réel. La victime saisit ses
identifiants sur une page contrôlée par l'attaquant, qui les rejoue
immédiatement sur le vrai site ; celui-ci envoie un code authentique, que la
victime reçoit et saisit à son tour sur la fausse page. Le code est valide, le
message qui l'a apporté est authentique, et pourtant la session est volée.

Marqueurs observables : la page de connexion est atteinte depuis un lien reçu,
et non depuis un signet ou une recherche ; le domaine de la page diffère de
celui du service, même de peu ; l'enchaînement est inhabituellement rapide entre
un message d'alerte et une demande de connexion ; le message crée l'urgence qui
pousse à passer par son lien plutôt que par le chemin habituel.

Ce qui ne prouve rien : le message porteur du code est ici parfaitement
légitime - il vient réellement du service. L'analyser seul ne révélera jamais
l'attaque. Ce qui la révèle est le message DÉCLENCHEUR, celui qui a conduit la
victime à se connecter. C'est pourquoi une alerte de sécurité inattendue
comportant un lien de connexion mérite plus d'attention que le code qui suit.

3. La lassitude du second facteur

L'attaquant, déjà en possession du mot de passe, déclenche des demandes de
validation en série jusqu'à ce que la victime accepte par usure ou par erreur.
Un message d'accompagnement se fait parfois passer pour le support informatique
et demande d'approuver « pour arrêter les notifications ».

Marqueurs observables : message invitant à approuver une demande de connexion
que le destinataire n'a pas initiée ; prétendu support demandant d'accepter une
notification ; répétition anormale d'alertes de connexion.

Ce qui ne prouve rien : une alerte de connexion non reconnue est souvent
authentique et constitue précisément le signal que le service est censé
envoyer. Elle doit conduire à changer le mot de passe par le chemin habituel,
pas à répondre au message.

4. Le faux support technique

Le message annonce un problème - compte suspendu, activité suspecte, mise à jour
de sécurité - et propose une assistance. L'objectif est d'obtenir un code, un
accès à distance, ou l'installation d'un logiciel de prise en main.

Marqueurs observables : numéro de téléphone à rappeler fourni dans le corps du
message ; invitation à installer un outil d'assistance à distance ; demande de
communiquer un code pendant l'appel ; adresse de réponse sur un domaine
générique alors que le service prétendu dispose du sien.

Ce qui ne prouve rien : les services d'assistance légitimes existent et donnent
leurs coordonnées. Le marqueur n'est pas la présence d'un numéro mais le fait
que ce numéro soit le seul chemin de vérification proposé.

5. Le principe qui gouverne cette famille

Le sens de la circulation qualifie le message. Un secret qui descend vers le
destinataire est un service ; un secret qui remonte vers l'expéditeur est une
attaque. Devant un message qui parle de code, la question n'est jamais « ce
message contient-il un code ? » mais « ce message demande-t-il au destinataire
de s'en dessaisir ? ».
